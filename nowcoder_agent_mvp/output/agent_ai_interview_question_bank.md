# Agent / AI 应用研发面试题库（MVP）

## 样本与口径

本题库基于牛客“最新”列表的两个二级类别，每类 30 篇，共 60 篇；未使用三级标签。逐篇阅读正文后，纳入 17 篇高相关样本。关键词只负责召回，最终筛选由正文语义决定。

频度标记只反映这 17 篇 MVP 样本：

- **高频**：多篇面经反复出现，且常有二到三层追问。
- **中频**：在不同公司或不同场景中出现数次。
- **代表性**：样本次数不多，但很能区分候选人的工程深度。

---

## 一、Agent 架构与选型

### 1. 什么是 Agent？它和普通的大模型 API 调用有什么本质区别？（高频）

**参考答案：**普通 LLM 调用主要是“输入→生成”；Agent 则是围绕目标运行的可控制循环，至少包含状态、规划/决策、工具执行、观察反馈和停止条件。生产系统还应有权限、重试/降级、记忆、审计、成本与评测。回答时要强调：工具调用不是唯一区别，“闭环决策与状态化执行”才是核心。

### 2. 请画出一个 Agent 应用从用户输入到结果返回的完整链路。（高频）

**参考答案：**可按“接入层→会话/权限→意图与路由→上下文构建→规划器→工具执行器→结果校验→流式输出→日志/评测”来画。每层说清输入输出、状态存储和失败边界，再补充用户取消、超时、幂等、人工确认与审计点。

### 3. ReAct 和 Plan-and-Execute 有什么区别？如何选型？（高频）

**参考答案：**ReAct 每步根据最新观察决定下一步，适合不确定性高、需要动态调整的任务，但延迟和 Token 成本高，也容易路径震荡。Plan-and-Execute 先产生计划再执行，适合长链路、可并行和可检查任务，但环境变化时需重规划。实际常采用分层混合：顶层计划，子任务内 ReAct，每个里程碑校验并允许局部重规划。

### 4. Workflow 和自主 Agent 的边界是什么？“80% 确定 + 20% 不确定”的任务怎么做？（高频）

**参考答案：**稳定、高合规、可枚举的步骤用 Workflow；需要自由规划和工具选择的部分交给 Agent。混合方案是用确定性状态机包住 Agent，只在指定节点开放自由决策，并设置预算、权限和人工确认门。

### 5. Prompt Engineering、Context Engineering 和 Harness Engineering 分别解决什么问题？（中频）

**参考答案：**Prompt Engineering 优化单次指令；Context Engineering 决定模型每步能看到哪些记忆、检索结果、工具描述和历史；Harness Engineering 是包裹模型的完整执行系统，负责调度、状态、工具、沙箱、重试、观测、成本和策略约束。

### 6. 怎样设计一个兼容多家模型的通用 Agent Runtime？（代表性）

**参考答案：**抽象统一的 Model Adapter，规范化 message、stream、tool schema、usage 和 error；上层保持与模型无关的计划、工具、记忆和评测接口。通过能力矩阵做路由，配合超时、熔断、幂等重试和备用模型故障转移。

## 二、工具、Skill、MCP 与执行循环

### 7. Function Call 时模型返回的是真实工具结果，还是调用意图？（中频）

**参考答案：**模型通常只返回工具名和结构化参数，它是调用意图；真正执行由应用端的 Tool Executor 完成。执行前要做 schema 校验、权限检查、幂等键和超时预算，执行后把可审计的 observation 回填给模型。

### 8. Tool Call 参数不合法时怎么处理？（高频）

**参考答案：**先用 JSON Schema/类型系统校验；对可修复错误返回结构化错误并限次自修复；对越权或高风险参数直接拒绝；超过重试上限后降级、请用户补充或转人工。错误类型必须区分，不能对所有失败盲目重试。

### 9. 工具返回超长结果，不能直接截尾，应如何处理？（高频）

**参考答案：**先保留 schema、错误、统计和用户指定字段；大结果存入外部存储，上下文只放句柄、摘要和可导航索引；再用分块、结构化聚合或 map-reduce 摘要按需取数。截断前应基于任务目标做信息优先级，并保留回溯原始结果的能力。

### 10. Agent 反复调用同一工具或陷入死循环，怎么检测和终止？（高频）

**参考答案：**设置最大步数、时间和 Token/费用预算；对“工具+规范化参数+结果摘要”做指纹，检测重复状态和无进展回合；连续无进展时强制重规划、切换策略或停止。高风险任务还应把循环上限写入策略层，不交给模型自己决定。

### 11. Skill 是什么？当 Skill 有 1000 个时怎么加载？（中频）

**参考答案：**Skill 是可复用的任务能力包，可包含说明、约束、工具、脚本和资源。不应把全部说明塞入 Prompt，而是用元数据粗召回、向量/关键词混合排序，只加载 Top-K 的详细内容。执行时再校验版本、权限、依赖和参数。

### 12. MCP 解决什么问题？它与业务 API 的关系是什么？（中频）

**参考答案：**MCP 是模型应用与外部工具/资源之间的标准协议层，统一能力发现、参数 schema、调用和结果传递。它不代替业务 API；MCP Server 可以封装现有 API，但认证、授权、幂等、审计和限流仍需在工程层实现。

### 13. 多 Agent 之间怎么通信？自然语言结果怎么避免解析出错？（中频）

**参考答案：**优先通过调度器和共享任务状态通信，消息使用带版本的结构化 schema，而不是把任意自然语言当协议。需要自然语言时，同时返回机器可读字段、置信度和原始证据，校验失败时请子 Agent 重试或转人工。

## 三、上下文、记忆与状态

### 14. 长对话的上下文如何压缩？哪些信息必须保留？（高频）

**参考答案：**建议分为近期原文窗口、结构化任务状态、历史摘要和可检索长期记忆。必留项包括用户目标、硬约束、已确认决策、未完成任务、工具的关键结果与来源。压缩后要用关键事实覆盖率、约束保真和下一步决策一致性做回归测试。

### 15. 三层记忆中摘要提错或漏掉关键信息，怎么发现与恢复？（中频）

**参考答案：**不只存一段自由文本摘要，同时存结构化事实、事件日志、版本和原文指针。摘要更新时对必留字段做差异检查；如后续决策与历史约束冲突，回溯原始事件重建上下文。

### 16. Agent 的短期记忆和长期记忆分别如何实现？（中频）

**参考答案：**短期记忆是当前会话和任务状态，常用 Redis/状态库并设 TTL；长期记忆是经用户同意后保存的稳定偏好、历史事件和可复用事实，用关系库/文档库加检索索引。写入应去重、标注来源和时效，读取时按权限、相关性和新鲜度排序。

### 17. 分布式 Agent 的 Session 和中间状态应该放在哪里？（中频）

**参考答案：**不应只放在单机内存。可恢复的快照和任务状态放集中式存储（如 Redis+持久库），调度通过幂等任务 ID、版本号或 CAS 避免重复执行。关键外部操作用事件日志/补偿保证可恢复，前端通过进度事件订阅状态。

## 四、RAG 与知识工程

### 18. 请说明 RAG 从文档入库到生成答案的完整流程。（高频）

**参考答案：**文档解析/清洗→按结构切片→元数据与权限绑定→稀疏/稠密索引→Query 改写→混合召回→重排→去重/压缩→带引用生成→置信度/拒答→日志和评测。要主动提到 ACL 过滤必须在召回和生成前生效。

### 19. Chunk 切得太长或太短分别有什么问题？无标题 Markdown 和长表格怎么切？（高频）

**参考答案：**太短会丢失上下文、增加碎片；太长会稀释向量语义并占用窗口。应优先按文档结构和语义边界切，再用 Token 上限和 overlap 兜底。无标题文档可先做版式/主题分段；表格 Chunk 应重复表头、主键和单位，保留行列关系。粒度最终用召回率和答案正确率实验决定。

### 20. 为什么要同时用稀疏和稠密检索？RRF 如何融合？（中频）

**参考答案：**稀疏检索擅长精确词、编号和罕见实体；稠密检索擅长语义改写和近义表达。RRF 对各路候选的排名计算 `1/(k+rank)` 后求和，避免直接比较不同分数空间。`k` 和各路权重应在验证集上调，再交给 reranker 精排。

### 21. RAG 召回率已经 90%+，但最终答案仍不准，怎么排查？（高频）

**参考答案：**建立分段评测：先看 gold evidence 是否在 Top-K，再看重排位置、上下文组装是否丢失，最后在“给定完整正确证据”条件下单测生成器。常见问题是噪声过多、冲突文档、旧知识未失效、Prompt 不要求引用证据，或模型不会从表格/长文中抽取。

### 22. 如何让知识库的旧制度失效、新制度立即生效？（代表性）

**参考答案：**文档和 Chunk 都带版本、生效时间、失效时间和来源。通过变更事件做增量解析与建索引，新版索引完成后原子切换别名，再延迟清理旧版。检索时按有效时间和版本过滤，同时刷新问答缓存。

## 五、评测、Bad Case 与准确性

### 23. Agent 评测体系应包含哪些维度？（高频）

**参考答案：**至少分五层：任务成功/业务结果；轨迹正确性（计划、工具选择、参数）；内容质量（事实性、完整性、引用）；工程指标（P95/P99、成功率、恢复率）；成本、安全和用户满意度。线下回归和线上指标要用同一套 case ID 串起来。

### 24. Golden Set 怎么构建？有 20%—30% 的答案带主观性怎么办？（高频）

**参考答案：**样本来自高频流量、高风险场景、历史 Bad Case 和边界输入，按业务分层抽样并做版本化。客观题用硬断言；主观题不强行只设一个标准答案，而是定义 rubric、必要事实和不可接受行为，多人标注并统计一致性。

### 25. LLM-as-Judge 可以用吗？有什么风险？（中频）

**参考答案：**可用于大规模初评和趋势比较，但会有位置偏置、长度偏置、自偏好、Prompt 敏感和不稳定。要用明确 rubric、打散顺序、多次/多模型投票，并用人工标注集做校准。高风险决策不能只靠 Judge。

### 26. Bad Case 出现后如何定位和回流？能否直接用失败轨迹做 SFT？（高频）

**参考答案：**先分解为数据/检索、Prompt/上下文、模型、工具、执行环境和评测标准问题，用 trace 重放找到首个错误节点。修复后加入回归集。失败轨迹不应原样直接做 SFT，否则会学到错误动作；应重建或标注正确轨迹，去除敏感信息，再按错误类型决定是数据、策略还是训练修复。

### 27. 怎么降低幻觉，并让系统在没有证据时拒答？（高频）

**参考答案：**把回答约束为“只根据已授权证据”，要求返回引用和证据片段；对召回置信度、证据冲突和关键字段完整性设阈值，不足时澄清或拒答。财务等高风险场景应用确定性 SQL/规则生成结果，LLM 只负责解释，并加权限、审计和人工确认。

## 六、生产化：稳定性、性能与成本

### 28. Agent 某一步执行失败时，重试、降级、回滚和部分结果返回怎么选？（高频）

**参考答案：**先按可恢复性分类：瞬时错误才做带退避的有界重试；可替代能力走备用工具/模型；已发生外部副作用用 Saga/补偿操作；无法完成但已有可用中间结果时，明示未完成部分后返回。全链路用幂等键、检查点和事件日志支持恢复。

### 29. 用户等了 20 分钟后取消任务，系统怎么停？（中频）

**参考答案：**取消是端到端的状态：API 写入 cancellation token，调度器停止发新步骤，执行器在安全点轮询并中止可中断工具。不可中断或有副作用的操作记录状态并执行补偿，最后保存检查点和部分结果，向用户返回“已停止到哪一步”。

### 30. 高并发 Agent 系统如何做资源隔离和背压？（高频）

**参考答案：**接入层按租户/用户限流，队列把接收和执行解耦；调度器按模型、工具和沙箱分资源池，设并发信号量、优先级和队列上限。超载时延迟、降级或拒绝，而不是无界堆积。对沙箱设 CPU/内存/时间配额，状态外置以支持容器重启恢复。

### 31. Token 成本和延迟怎么系统性优化？（高频）

**参考答案：**先埋点分解每步的 input/output Token、模型耗时和工具耗时，再优化：简单任务路由小模型；缓存稳定结果和 Prompt 前缀；只加载必要的 Skill/记忆/检索片段；并行无依赖工具；对超长结果外置。优化以任务成功率和单次成功成本为主，不能只压 Token。

### 32. 模型 API 响应慢或挂了，如何让用户尽量无感？（中频）

**参考答案：**设分阶段超时和可取消请求，瞬时错误有界重试；用熔断和健康检查切到能力等价的备用模型；用流式输出、进度事件和异步任务改善感知延迟。故障转移要保存幂等键和上下文版本，防止重复执行。

### 33. 大模型回答如何流式推送？SSE、WebSocket 和轮询怎么选？（中频）

**参考答案：**单向 Token/进度推送优先 SSE，协议简单且易穿过网关；需要高频双向交互、即时取消或协作时用 WebSocket；长任务还应提供任务 ID 的查询兜底。流中的每个事件带序号，断线重连后可从断点继续。

## 七、安全、权限与多租户

### 34. Agent 执行代码或命令时，沙箱怎么设计？（高频）

**参考答案：**默认无权限，每任务短命隔离；只挂载允许目录，文件系统尽量只读，网络域名/IP 白名单，限制 CPU、内存、进程数、输出和运行时间。凭证用短期令牌按工具授权，不注入长期密钥。破坏性操作在策略层拦截，高风险动作需用户确认，所有调用留审计日志。

### 35. 多租户 Agent 平台的权限如何做？创建阶段和查询阶段有什么不同？（高频）

**参考答案：**所有 Agent、会话、文档、Chunk、工具凭证和评测数据都绑定 tenant/user 边界。创建阶段检查用户能否引用数据源、工具和模型；查询阶段再根据当前用户做行/列/文档级过滤，不能因为 Agent 由管理员创建就继承管理员的数据权限。

### 36. 怎么防 Prompt Injection 和工具越权？（中频）

**参考答案：**把用户输入、检索文档和工具输出都当作不可信数据，不与系统指令拼接为同一信任级。真正的安全边界在模型外：工具白名单、参数校验、最小权限、数据 ACL、出站过滤和高风险确认。再用攻击样本和越权样本做持续回归。

## 八、场景设计与 AI Coding

### 37. 用户说“我想找个好吃的”，Agent 怎么澄清，什么时候停止追问？（高频）

**参考答案：**先提取完成任务的最小槽位，如地点、时间、预算、人数、口味/忌口和距离；每轮优先问信息增益最大且用户容易回答的问题。当关键槽位齐全、候选集足够小，或达到轮次/时间预算时停止；如仍不确定，明示假设并允许用户修正，不应简单把“三轮”当普遍规则。

### 38. 设计“周末南京两日、预算 2000”的行程 Agent；遇到下雨或临时压缩为一天怎么处理？（代表性）

**参考答案：**先澄清出发地、交通、兴趣、硬时间和预算分配；将天气、地图、交通、景点和价格工具封装为幂等调用。计划产出带时间/费用/风险的结构化日程，下单前必须用户确认。天气变化时只重规划受影响区段；压缩为一天时保留硬约束和用户高优兴趣，并展示删减取舍。

### 39. 你的 AI Coding 工作流是什么？如何确保生成代码的质量？（高频）

**参考答案：**先人工明确需求、约束、验收条件和相关代码范围；让 AI 先给方案和风险，再分小步修改。人工 review 业务正确性、边界、并发、安全、复杂度和架构一致性，并通过编译、静态检查、单测/集成测试、依赖与密钥扫描。AI 连续多次修复失败时，停止盲试，缩小复现、自己定位根因，重建上下文后再委派局部任务。

### 40. Agent 直接从需求生成代码并上线，有哪些风险？质量门禁怎么设计？（中频）

**参考答案：**风险包括需求理解错误、隐性边界遗漏、依赖/许可证问题、注入安全漏洞、架构腐化和错误发布。流水线应包含变更范围限制、必需人工 review、编译/测试/扫描、预发验证、灰度和指标门禁。发布采用可回滚制品和原子流量切换，异常时自动停止或回滚，不允许 Agent 绕过审批和审计。

## 高频追问链（建议按项目准备）

1. **你做了什么？** → 为什么这样选？ → 替代方案是什么？ → 数据如何证明有效？
2. **正常链路怎么跑？** → 工具超时呢？ → 重试也失败呢？ → 已有副作用如何回滚？
3. **上下文怎么压缩？** → 什么叫关键信息？ → 怎么量化信息丢失？ → 丢错后怎么恢复？
4. **RAG 怎么做？** → 切片粒度怎么定？ → 混合召回怎么融合？ → 召回对但答错怎么定位？
5. **评测集怎么建？** → 主观题怎么标？ → LLM-as-Judge 怎么校准？ → 线下好线上差怎么查？
6. **系统能跑了吗？** → 用户量/QPS/P99 是多少？ → 单任务 Token/成本是多少？ → 最严重的线上故障是什么？

## 本轮语义筛选结论

- 主要考察不是某个框架 API，而是能否把 Agent 做成“可控、可评测、可恢复、可审计”的生产系统。
- 最集中的主题是：整体架构、上下文/记忆、工具失败与死循环、RAG 分段评测、Agent 评测、成本/延迟和 AI Coding 质量兜底。
- 后端类别确实补到了人工智能类别中容易漏掉的服务化问题：分布式 Agent、流式输出、状态存储、并发、缓存、幂等与故障恢复。
