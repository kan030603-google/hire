# 牛客 Agent / AI 应用面经

把当前会话作为编排器，将确定性采集交给项目代码，将大批量语义工作交给指定模型的子代理。不要要求用户在阶段之间手动切换模型，不要使用 OpenAI API Key。

## 工作目录

1. 用 `git rev-parse --show-toplevel` 定位仓库根目录。
2. 使用仓库根目录下的 `nowcoder_agent_mvp` 作为执行项目。
3. 读取 `config/collection.september-2026.json` 和其中引用的企业注册表；除非用户明确修改范围，否则不得绕过企业筛选、扩大类别或抓取时间窗外内容。
4. 运行或修改文件前遵守仓库的 `AGENTS.md`。写入运行产物前保留已有成功记录并采用断点续跑。

## 模式

- 用户要求“测试、冒烟、先跑通”时使用冒烟模式：只选一个企业组和一个二级类别，验证列表加载、详情抓取、抽题、整理和终审。列表阶段目标为 30 篇或滚动至早于时间窗起点，以先达到者为准。全部测试产物写入 `data/smoke-test/` 和 `output/smoke-test-question-bank.md`，不得覆盖正式数据。
- 用户要求正式采集时使用完整模式：执行采集计划中的全部未完成单元，直至越过时间窗起点。当前月份只采集截至当天可见的帖子，并保留增量续抓状态。
- 用户仅要求重整已有数据时，从现有正文开始，不重复访问牛客。

## 执行流程

### 1. 预检与计划

由主代理运行 `python nowcoder_agent_mvp/scripts/build_collection_plan.py`，确认：

- 所有执行单元都有至少一个已核对的牛客企业选择器；
- 只包含 `软件开发 / 人工智能/算法` 与 `软件开发 / 后端开发`，不选择三级岗位标签；
- 排序为“最新”，且 `rejectUnfilteredQueries` 为 `true`；
- 时间窗、企业组数和采集单元数与配置一致。

任何单元无法应用企业筛选时，记录失败并跳过该单元，不得退化为“全部企业”。

### 2. 采集

创建一个子代理，明确指定 `gpt-5.6-terra`、`medium`。让它：

- 读取采集计划和已有断点；
- 使用牛客自带企业选择器和两个二级类别；
- 处理无限滚动，采集列表元数据，再调用项目正文抓取脚本；
- 在详情层运行 `scripts/clean_posts.py`，二次执行时间窗、明确的他公司标题误召回、URL 和内容指纹检查；
- 将被拒绝记录与原因写入隔离文件，只把清洗后的正文交给语义阶段；
- 若未到时间窗起点且有效正文不足 30 篇，继续下拉补齐；若已越过起点，不为凑数纳入窗口外帖子；
- 每个单元写入完成、跳过或失败状态，最多重试三次；
- 返回计数和阻塞原因，不生成最终题库。

登录失效、验证码、权限页或网站结构变化时停止对应单元并报告，不尝试绕过。

### 3. 语义筛选与抽题

采集与确定性清洗完成后创建 `gpt-5.6-luna`、`medium` 子代理。让它读取 [筛选标准](references/screening-policy.md) 和 [数据契约](references/data-contracts.md)，只分批处理 `clean-posts.jsonl` 并输出结构化题目。关键词只能用于召回提示，是否纳入必须依据正文语义。每条题目保留内部来源标识，`evidence` 必须能在该来源正文中定位；最终交付不得变成链接列表。

### 4. 归并与追问链

抽题完成后创建 `gpt-5.6-terra`、`medium` 子代理。让它按能力主题合并语义重复题，保留公司频次、出现次数、原始问法差异和连续追问关系。不得把只共享一个宽泛名词的不同问题强行合并。

### 5. 终审与答案

归并完成后创建 `gpt-5.6-sol`、`high` 子代理。让它检查遗漏、误合并、事实错误和答案质量，只修正有证据的问题。最终输出是按主题组织的题库与参考答案，不以来源链接为主体。

### 6. 完成判定

主代理验证各阶段产物符合 [数据契约](references/data-contracts.md)，汇总：

- 计划、完成、失败和跳过的采集单元数；
- 候选帖、成功正文、相关帖子和最终题目数；
- 误召回、时间窗外、重复内容的隔离数量与原因；
- 最早与最晚发布日期；
- 未完成原因及可续跑入口；
- 各阶段实际使用的子代理模型。

只有所有非阻塞阶段通过契约检查后才报告成功。冒烟测试成功不等于完整月份采集完成。
